# CHANGELOG — 2026-10-12

# Firm Wide Dashboard, App-Wide Dark Mode, Hard-Coded User Login Fix

## 1. Hard-coded user login fix (`backend/auth.py`)
- Root cause: `authenticate_user()` and `get_current_user()` looked users up
  by the `USERS` **dict key** (e.g. `"Cody_Spencer"`), not by the inner
  `"username"` value (`cpencer@quillarrow.com`). Logging in with the email
  therefore failed with "Incorrect username or password"; even a key-based
  login would then have failed on `/api/auth/me` because the JWT subject is
  the inner username.
- Added `find_user()` which matches on the `"username"` field,
  case-insensitively and whitespace-tolerant. Both login and token
  verification use it. Dict keys are now labels only.
- Updated the "To add a user" comment at the top of the user store.
- No change to passwords, roles, or JWT handling.

## 2. Firm Wide Dashboard — backend (`backend/routes/firm_dashboard.py`, NEW)
- New matters cache (`matters_cache` + `matters_cache_meta` tables, created
  with `Table.create(checkfirst=True)` — SQLite locally, Azure SQL in prod).
  Rows store id, display_number, description, status, open/close/pending
  dates, `filed_date` (custom field 19020488 "Matter Filed Date"),
  `jurisdiction_option_id` + resolved `jurisdiction` (custom field 8835211:
  4702486→Federal, 4702471→State, 10733393→Arbitration, blank→State).
- `POST /api/firm/refresh` — background thread pull of matters from Clio
  (`matters` index with `custom_field_values{id,value,custom_field}`), DB lock
  so only one runs, 409 if already running. First run / `?full=true` is a
  full pull that also purges matters Clio no longer returns; later runs are
  incremental via `updated_since`. Returns immediately (Azure 230s rule).
- `GET /api/firm/refresh/status` — idle | running | ok | error, cache age,
  cached count (same polling contract as billing).
- `GET /api/firm/summary?date_from&date_to&jurisdiction` — `totals`
  (filtered) and `by_jurisdiction` {State, Federal, Arbitration}, each with
  total/open/pending/closed; plus `unfiled_matters` (no Filed Date) and
  `cached_matters`. Default window = trailing 12 months.
- `GET /api/firm/trend?date_from&date_to&granularity=day|week|month` —
  flat rows of (period, jurisdiction, status, count) so both charts' dropdowns
  filter client-side; only the interval triggers a re-query.
- Registered in `backend/main.py`.

## 5. Dark Mode on all remaining pages
- `MattersPage`, `CustomFieldsPage`, `BulkOperationsPage`,
  `TemplateMassUpdatePage`, `AuditLogPage`, `LoginPage`: added `dark:`
  variants to every surface/text/border/badge class (cards → slate-800,
  tables/headers → slate-700, text → slate-100/200/300/400, alert banners →
  -950 backgrounds with -200 text, etc.). Toggle-switch knob stays white.
- `frontend/src/index.css`: dark-mode baseline for form controls
  (`input`/`select`/`textarea` → slate-700 surface, slate-100 text,
  slate-600 border, `color-scheme: dark` for native date pickers).
  Checkboxes, radios, file inputs untouched.
- With this, every page in the app (plus header/sidebar) is dark-mode
  themed. The Settings route has no page yet.
